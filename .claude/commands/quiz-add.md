`questions.js`에 새 문항을 더합니다. 카테고리 4개(`한국사`, `세계지리`, `과학`, `예술과 문화`) 모두에 **같은 수 n개**씩 만들어 카테고리마다 문항 수가 같게 유지합니다.

인수: `$ARGUMENTS` (더할 개수 n, 카테고리당. 1 이상의 정수여야 합니다. 아니면 더하지 말고 값을 물어봅니다.)

## 지킬 것

- 문항은 `CLAUDE.md`의 "문항 작성 규칙" 10개와 "이 저장소에서 더한 규칙"을 지켜서 만듭니다. 규칙은 이 파일에 옮겨 적지 않습니다. `CLAUDE.md`를 읽고 따릅니다.
- 출처는 **실제로 열어서 확인**합니다. 위키백과, 나무위키, 블로그는 쓰지 않습니다. 확인하지 못한 출처를 적거나 지어내지 않습니다. 서로 다른 기관 2곳의 값이 어긋나면 그 사실은 버리고 다른 주제로 바꿉니다.
- 문서를 가져오는 도구가 막히면(403, 확인 화면 등) 우회하지 말고 다른 출처로 바꾸고, 어떻게 확인했는지 보고에 밝힙니다.
- **사람이 승인하기 전에는 `questions.js`를 고치지 않습니다.** 승인 전에는 문항 전문과 검수표만 보여 줍니다.
- 커밋하지 않습니다. 파일만 고친 뒤 멈추고, 브랜치와 병합은 사람이 합니다. `git` 명령을 쓰지 않습니다.
- `.claude/commands/`의 다른 명령 파일은 고치지 않습니다.

## 순서

1. **상태 확인:** `questions.js`의 카테고리별 문항 수를 센다(`node -e`로 `require('./questions.js').QUESTIONS`를 읽기만 한다). 카테고리마다 수가 다르면 **여기서 멈추고** 어느 카테고리가 몇 개인지 알린다.
2. **기존 문항 읽기:** 모든 기존 문항을 읽으면서 문항마다 id와 함께 인물, 사건, 작품, 지명을 적어 둔다. 새 문항이 이 주제와 겹치지 않게 하려는 것이다.
3. **새 문항 만들기:** 카테고리마다 n문항을 `questions.js` 형식(`id`, `category`, `question`, `choices`(4개), `answer`, `explanation`, `source`)으로 만든다. id는 카테고리별 다음 번호(`history-11`, `geography-11`, `science-11`, `culture-11`, …)로 하고 전체에서 유일해야 한다. 정답 번호는 한쪽으로 몰리지 않게 섞는다.
4. **출처 확인과 중복 확인:**
   - 문항마다 서로 다른 기관 2곳(A, B)을 실제로 열어 사실을 대조한다. 두 곳의 값이 같을 때만 쓴다. `source`에는 둘 중 근거가 더 분명한 1곳의 기관명과 주소를 적는다.
   - 최상급 표현이 있으면 문제에 기준과 시점을 적었는지 확인한다.
   - **기존 문항과 겹침 확인:** 2단계에서 적어 둔 인물·사건·작품·지명과 같은 주제인 기존 문항이 있으면 그 id를 기록한다. **겹치는 문항은 보여 주지 말고 다른 주제로 바꿔** 3~4단계를 다시 한다.
5. **문항과 검수표 보여 주기:** 새 문항 전문(코드 블록)과 아래 검수표를 보여 준다. 검수표의 `기존 문항과 겹침` 칸에 id가 남아 있으면 표를 보여 주지 말고 4단계로 돌아간다.

   | id | 정답 | 출처 A에서 확인한 내용 | 출처 B에서 확인한 내용 | 두 출처 일치 | 정답 하나뿐 | 최상급 기준·시점 | 기존 문항과 겹침 |
   |---|---|---|---|---|---|---|---|

   - 출처 A, B 칸에는 기관명과 그곳에서 읽은 내용을 짧게 적는다. 확인하지 못했으면 `확인 못함`이라고 적고 그 문항은 바꾼다.
   - `최상급 기준·시점` 칸은 최상급 표현이 없으면 `해당 없음`, 있으면 문제에 적은 기준과 시점을 적는다.
   - `기존 문항과 겹침` 칸은 겹치는 기존 문항이 없으면 `없음`이다(겹치는 문항은 4단계에서 이미 바뀌었으므로 표에서는 늘 `없음`이어야 한다).
6. **승인 기다리기:** "승인하시면 `questions.js`에 넣겠습니다. 문제가 있는 문항은 id로 알려 주세요."라고 묻고 **멈춘다.**
   - 사람이 일부만 승인하거나 일부를 거절하면 거절한 문항만 새 주제로 다시 만들어 5단계부터 다시 보여 준다. 카테고리마다 문항 수가 같아야 하므로 일부만 넣지 않는다.
   - 승인하지 않았거나 승인을 기다리는 동안에는 파일을 고치지 않는다.
7. **반영과 검증(승인 뒤에만):** 새 문항을 `questions.js`의 해당 카테고리 끝에 `Edit`으로 넣는다. 그다음 읽기 전용으로 확인한다.

   ```
   node -e "const q=require('./questions.js').QUESTIONS; const s=require('./script.js'); console.log('문항 ' + q.length + '개'); const e=s.validateQuestions(q).concat(s.checkCategoryCounts(q)); console.log(e.length ? e.join('\n') : '검사기 위반 없음, 카테고리마다 문항 수 같음')"
   ```

   검증을 통과하지 못하면 **멈추고** 무엇이 문제인지 보고한다. 고치기 전에 사람에게 묻는다.
8. **보고:** 더한 문항 수(카테고리마다 n개, 총 몇 개), 카테고리별 문항 수, 검증 결과, 확인하지 못했거나 우회한 출처 확인 방법을 적는다. 중복되어 바꾼 주제가 있으면 무엇이 어느 기존 문항(id)과 겹쳤는지 밝힌다. 마지막에 "커밋하지 않았습니다. 브랜치와 병합은 사람이 하세요."라고 덧붙인다.

## 멈추는 경우

- 카테고리별 문항 수가 다를 때(1단계)
- 사람이 승인하지 않았거나 승인을 기다릴 때(6단계)
- 반영 뒤 검증이 통과하지 못했을 때(7단계)
